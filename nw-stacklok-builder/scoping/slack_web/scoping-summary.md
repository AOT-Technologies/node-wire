### Flagged Issues

- 91 POST endpoints carry their real fields in an `application/x-www-form-urlencoded` request body that `mcp-builder analyze` does not enumerate. The scoped body fields were read directly from the spec. The validator emits 44 "body parameter not found in spec's requestBody, type will default to str" warnings for them. This is expected for form bodies (see the generator contract), and every one of those fields is `type: string` in the spec anyway. The user accepted these warnings.
- 155 endpoints declare Slack's legacy `token` parameter (a header on POSTs, a query parameter on GETs). It is excluded from every tool; the bot token goes in `Authorization: Bearer`.
- The spec marks many fields optional that Slack actually requires. They were overridden to `required: true` in the scope (see Phase 2 checklist).
- Slack `ts` values are typed `number` in several places (`conversations.history` latest/oldest, `conversations.replies` ts/latest/oldest, `chat.delete` ts, `chat.scheduleMessage` thread_ts). They must be sent as strings to keep microsecond precision. Hints note this on each tool.
- The spec's scope catalog mixes legacy scopes (`bot`, `chat:write:bot`, `channels:write`) with granular ones, includes a pseudo-scope `none`, and lacks `chat:write.public` / `channels:join`.
- Several GET operations change state (`views.*`, `dialog.open`, `workflows.*`, `apps.uninstall`, `auth.revoke`). None of them are in scope.
- The 56 `admin.*` endpoints need Enterprise Grid plus an admin user token, and `search.messages` needs a user token. None of these are usable with a bot token.
- Legacy or superseded endpoints exist (`oauth.access`, `oauth.token`, `rtm.connect`, `dialog.open`, `files.upload`, `stars.*`, `workflows.*`). None are in scope.

## Auth Detection

- **Selected auth type:** api_key
- **Source scheme:** slackAuth (oauth2, authorizationCode)
- **Rationale:** The user will use a static Slack bot token (`xoxb-...`). Slack accepts it as `Authorization: Bearer`, which is exactly what the generator's `api_key` type forwards. The token's bot scopes are configured in the Slack app, not in the scope file. The needed scopes are listed in `auth.notes`: chat:write, chat:write.public, chat:write.customize (optional), channels:read, groups:read, im:read, mpim:read, channels:history, groups:history, im:history, mpim:history, channels:join, im:write, mpim:write.

### Alternative Schemes

| Scheme | Type | Why Not Selected |
|--------|------|-----------------|
| slackAuth | oauth2 (authorizationCode) | Points at Slack's legacy v1 flow (`/oauth/authorize`, `oauth.access`), which does not issue modern bot tokens; scope catalog uses legacy names |
| (Sign in with Slack) | oidc | Not declared in the spec; Slack's OIDC grants only identity scopes, not API scopes like `chat:write` |
