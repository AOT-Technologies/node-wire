### Flagged Issues

- No endpoint has a `summary`. Descriptions are terse one-liners, so tool descriptions were written from Slack's API docs, not the spec.
- The only declared scheme is a legacy v1 OAuth2 authorization-code flow. The deployment uses a static `xoxb-` bot token instead.
- 155 endpoints declare an explicit `token` header or query param. The connector builder drops these as credential params, and none appear in tool parameters.
- 91 endpoints use `application/x-www-form-urlencoded` bodies. `mcp-builder validate` doesn't read form fields, so it warns for every body parameter (23 warnings in this scope). All 23 fields were checked against the spec's form schemas and exist. The user accepted the warnings.
- The spec leaves some parameters optional that Slack requires in practice: `channel` on `conversations.info`/`join`, and `channel` + `ts` on `conversations.replies`. They were left optional, as the spec declares, and each description says "Required by Slack in practice".
- The spec types some Slack timestamps (`ts`, `oldest`, `latest` on `conversations.replies`) as `number`. Slack `ts` values must be sent as exact strings.
- Only one workflow was provided.
