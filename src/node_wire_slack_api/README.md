## Authentication

**Host-supplied credential.** Node Wire presents `SLACK_API_ACCESS_TOKEN` as an
`Authorization: Bearer` header and never obtains, refreshes, or detects the
expiry of it — scheme `slackAuth` in the source spec is an OAuth2 /
OpenID Connect scheme, and the host application owns acquiring and rotating
the token entirely out-of-band. A stale token surfaces as a plain `401`.

Build notes:

- HOST-SUPPLIED CREDENTIAL: scheme 'slackAuth' declares oauth2 flow(s) ['authorizationCode']. Node Wire never acquires this credential — the host application must obtain it (e.g. complete the provider's own auth flow) and set SLACK_API_ACCESS_TOKEN itself. Node Wire will present whatever value is there as a Bearer token but performs no refresh and detects no expiry; a stale token surfaces as a plain 401 from the API, not a managed refresh cycle.
- Host auth documentation: authorizationUrl=https://slack.com/oauth/authorize
- Host auth documentation: tokenUrl=https://slack.com/api/oauth.access

### Storing credentials per tenant

`logic.py` calls `declare_secret_shape()` at import time, so this connector's
secrets can be written through the config store per tenant/config even under
`NW_SECRET_SHAPE_POLICY=enforce`. Without that declaration the store refuses
credentials for connectors it does not recognise.
